# AI 仪表盘与 DeerFlow Runtime Control Plane 计划

## Summary

新增 `AI仪表盘` 入口，用来展示完整 AI Runtime 状态。架构定位调整为：FacetWrite 是用户工作空间、配置入口、交互界面和审批层；DeerFlow 是真正执行任务的 Agent Runtime，负责主 Agent、子 Agent、ToolUse、MCP 与智能编排。`Agent设置` 面向用户配置具体 Agent，`AI仪表盘` 面向运行状态、能力映射和系统可观测。

## Key Changes

- **新增导航入口**
  - 在左侧导航新增：
    - 中文：`AI仪表盘`
    - 英文：`AI Dashboard`
  - 入口位置建议放在 `Agent设置` 与 `知识库设置` 之间。
  - 不命名为 `DeerFlow映射`，避免显得只是后端调试页。

- **明确页面分工**
  - `Agent设置`：
    - 用户配置具体 Agent。
    - 包括模型、提示词、Skills、MCP Tools、记忆、短语、输出格式、工具开关。
    - 目标是给用户配置自主权。
  - `AI仪表盘`：
    - 展示整体 AI Runtime 状态。
    - 不编辑具体 Agent prompt。
    - 展示 DeerFlow 是否在线、认证状态、主 Agent、子 Agent、Skills、MCP servers、ToolUse 能力、运行事件和桥接进度。
  - `FacetWrite 工作区`：
    - 提供 Canvas、聊天、审批、写入位置选择、用户确认与结果展示。

- **架构语义调整**
  - 文档和 UI 文案统一为：
    - FacetWrite 是 workspace/control plane。
    - DeerFlow 是 execution/runtime plane。
  - 避免描述成 “FacetWrite 本地工具 vs DeerFlow 工具”。
  - 改成：
    - `已桥接到 DeerFlow Tool`
    - `待桥接为 DeerFlow Tool`
    - `由 FacetWrite 审批执行`
    - `仅用于产品层展示/写入`

- **AI 仪表盘内容**
  - Runtime 状态：
    - enabled
    - reachable
    - authState
    - baseUrl
    - assistantId / lead agent
    - current provider
  - DeerFlow 能力概览：
    - Skills 数量与列表
    - MCP server 数量与列表
    - MCP server 类型、启用状态、是否含 secret redaction
  - Agent Runtime 映射：
    - FacetWrite AgentCard
    - 对应 DeerFlow subagent
    - 传入的 skills
    - 传入的 tools
    - 模型继承/覆盖状态
    - 当前是否只是 metadata，还是已验证 DeerFlow 消费
  - ToolUse 桥接状态：
    - `CanvasWrite`：目标是 DeerFlow Tool，执行结果仍需 FacetWrite pending approval。
    - `KnowledgeBase`：目标是 DeerFlow 可调用知识工具或 MCP resource。
    - `WebSearch`：目标是 DeerFlow Tool/MCP search 能力。
    - `QuickMessages` / `ClearContext`：更偏 FacetWrite 产品交互，可视情况保留在前端/协议层。

- **新增后端只读接口**
  - 新增 `GET /api/deerflow/dashboard`。
  - 聚合：
    - `/api/deerflow/status`
    - `/api/deerflow/config`
    - AgentCard → DeerFlow subagent mapping
    - ToolUse bridge status
  - 不返回 API key、cookie、CSRF、MCP secret、provider secret。
  - 只读，不写 DeerFlow 配置。

- **文档更新**
  - 更新 `docs/ARCHITECTURE.md`：
    - FacetWrite = workspace/control plane。
    - DeerFlow = AI execution/runtime plane。
  - 更新 `docs/AGENT.md`：
    - Agent 设置负责用户配置。
    - DeerFlow 负责真实执行。
    - FacetWrite 工具能力逐步桥接为 DeerFlow Tool。
  - 更新 `docs/API.md`：
    - 记录 `/api/deerflow/dashboard`。
  - 更新 `docs/DECISIONS.md`：
    - 记录“FacetWrite 不作为独立主 Agent，DeerFlow 是主执行 runtime”的设计决策。
  - 更新 `docs/REFACTOR_LOG.md`：
    - 记录 AI 仪表盘入口、运行层可观测和 ToolUse 桥接状态。

## Test Plan

- `npm.cmd run typecheck`
- `npm.cmd test`
- 单元测试：
  - `/api/deerflow/dashboard` 返回 runtime、skills、MCP、agent mapping、tool bridge status。
  - dashboard 不返回 secret-like 字段。
  - DeerFlow disabled 时 dashboard 显示 TypeScript fallback / runtime inactive。
  - DeerFlow authenticated 时 dashboard 显示 `authState:"authenticated"`。
- 前端手动验证：
  - 左侧导航出现 `AI仪表盘`。
  - 点击后进入独立页面。
  - 页面展示 DeerFlow online/authenticated。
  - 页面展示 Skills、MCP servers、Agent 映射。
  - 页面清楚区分：
    - 已接入 runtime
    - 已传递配置
    - 已验证消费
    - 待桥接 ToolUse
  - `Agent设置` 页面仍只负责具体 Agent 配置。

## Assumptions

- FacetWrite 长期定位为工作空间、配置入口、交互窗口、审批与数据边界。
- DeerFlow 长期定位为真正的 Agent Runtime。
- CanvasWrite、KnowledgeBase、WebSearch 等能力未来会逐步桥接为 DeerFlow Tool 或 MCP 能力。
- 即使 Tool 由 DeerFlow 调用，高风险写入仍必须经过 FacetWrite Human-in-the-loop 审批。
- 本阶段只做 AI 仪表盘和只读 runtime 可观测，不开放 DeerFlow 写配置 UI。
- 不迁移数据库 schema。
- 不移除 TypeScript fallback。
