# DeerFlow Auth 闭环计划：自动本地会话

## Summary

让 FacetWrite 后端以合法登录态访问 DeerFlow 受保护 API，完成 `/api/skills`、`/api/mcp/config`、`/api/runs/stream` 的真实调用闭环。采用“自动本地会话”方案：FacetWrite 不绕过 DeerFlow auth，不把 DeerFlow cookie 暴露给前端，只在后端维护 DeerFlow session cookie + CSRF token。

## Key Changes

- 新增 DeerFlow auth 配置：
  - `DEERFLOW_AUTH_EMAIL`
  - `DEERFLOW_AUTH_PASSWORD`
  - `DEERFLOW_AUTO_SETUP=true|false`，默认 `false`
  - `DEERFLOW_AUTH_TIMEOUT_MS`，默认 5000
- 新增后端 DeerFlow auth/session helper：
  - 先查 `/api/v1/auth/setup-status`
  - 若 `needs_setup:true` 且 `DEERFLOW_AUTO_SETUP=true`，调用 `/api/v1/auth/initialize`
  - 否则调用 `/api/v1/auth/login/local`
  - 从 `Set-Cookie` 提取 `access_token` 与 `csrf_token`
  - 缓存在 FacetWrite 后端内存中，不落库、不返回前端
- 所有 DeerFlow 受保护请求统一走 authenticated fetch：
  - `GET /api/skills`、`GET /api/mcp/config` 携带 `Cookie: access_token=...`
  - `POST /api/runs/stream` 携带 `Cookie: access_token=...; csrf_token=...` 与 `X-CSRF-Token`
  - 遇到 401/403 时清空 session，重登一次，再重试一次
- 扩展 FacetWrite DeerFlow 状态：
  - `/api/deerflow/status` 增加 `authState`
  - 推荐取值：`not_configured`、`setup_required`、`authenticated`、`auth_failed`
  - 不返回 email、password、cookie、token、CSRF 或 DeerFlow MCP secret
- 更新前端设置面板：
  - DeerFlow online 但未认证时显示“DeerFlow online, auth required”
  - 认证成功后显示“DeerFlow online, authenticated”
  - `/api/deerflow/config` 成功后展示真实 skills 数量和 MCP server 概览
- 保持分层边界：
  - DeerFlow 仍只作为 Agent runtime sidecar
  - FacetWrite 继续拥有 SQLite、Canvas、审批和产品数据
  - 不修改 DeerFlow auth middleware，不禁用认证，不开放 DeerFlow 写配置 UI

## Implementation Notes

- 新增 `server/deerflow/auth.ts`，集中处理 setup-status、initialize、login、cookie/CSRF 提取、session cache、authenticated fetch。
- 修改 `server/deerflow/client.ts` 和 `server/deerflow/proxy.ts`，从普通 `fetch` 切换为 authenticated fetch。
- 修改 `server/deerflow/status.ts`，在 enabled/reachable 之外检查 auth readiness，但 auth 失败不影响 `/health` reachable 判断。
- `.env.local.example` 增加 DeerFlow auth 示例字段；真实 `.env.local` 只本地使用，不提交 secret。
- 文档更新：

## Test Plan

- Unit tests:
  - setup required + auto setup disabled → `authState:"setup_required"`
  - setup required + auto setup enabled → initialize 成功并缓存 cookie/CSRF
  - setup 已完成 → login 成功并缓存 cookie/CSRF
  - 401/403 → 清 session、重登、重试一次
  - login 失败不泄露 password/cookie
  - config proxy 使用 authenticated fetch 后可读取 skills/MCP，并继续 redaction
  - run stream POST 带 `Cookie` 和 `X-CSRF-Token`
- Regression:
  - `npm.cmd run typecheck`
  - `npm.cmd test`
- Manual validation:
  - DeerFlow Docker sidecar running at `http://127.0.0.1:2026`
  - FacetWrite `.env.local` 设置 `DEERFLOW_ENABLED=true`、`DEERFLOW_BASE_URL=http://127.0.0.1:2026`、`DEERFLOW_AUTH_EMAIL`、`DEERFLOW_AUTH_PASSWORD`
  - `/api/deerflow/status` 返回 `reachable:true`、`authState:"authenticated"`
  - `/api/deerflow/config` 不再 401，且不泄露 secret
  - Task 卡片 generation 返回 provider `deerflow`
  - 关闭 DeerFlow 或禁用 `DEERFLOW_ENABLED` 后 TypeScript fallback 仍可工作

## Assumptions

- 采用自动本地会话方案，不使用手动 cookie 录入，也不禁用 DeerFlow auth。
- 本地 first-boot 可以用 `DEERFLOW_AUTO_SETUP=true` 自动初始化 admin；已有 admin 时只做 login。
- DeerFlow session 只缓存于 FacetWrite 后端进程内存，服务重启后重新登录。
- 本阶段不做多用户 DeerFlow 账号映射；FacetWrite 使用一个本地 service/admin 会话访问 DeerFlow sidecar。
- 本阶段不修改数据库 schema，不扩展 AgentToolUse，不让 DeerFlow 直接写 FacetWrite 数据库。
