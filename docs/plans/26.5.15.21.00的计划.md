# 基于历史演变的 FacetWrite 可维护性优化计划

## Summary

阅读当前维护文档后，优化方向需要从“普通全栈项目拆分”调整为“控制平面与执行平面分层加固”。

项目已经明确决策：FacetWrite 是 workspace/control plane，负责 UI、配置、SQLite、Canvas、人类审批；DeerFlow 是 AI execution/runtime plane，负责 Lead Agent、subagents、ToolUse、MCP、智能编排。这个方向记录在 [docs/ARCHITECTURE.md](/F:/.FinalProject/docs/ARCHITECTURE.md:1)、[docs/AGENT.md](/F:/.FinalProject/docs/AGENT.md:1)、[docs/DECISIONS.md](/F:/.FinalProject/docs/DECISIONS.md:1)。

所以新的重构重点不是“把 DeerFlow 当参考目录移走”，而是让 FacetWrite 的控制平面边界更清楚，并把 DeerFlow runtime bridge 做成稳定、可观察、可测试、可逐步扩展的集成层。

## 当前结构再评价

当前目录结构已经比早期计划成熟：历史计划中提到的 `server/index.ts` 巨型入口、重复 API client、Tool catalog 缺失等问题已经部分解决。现在已有 [server/app.ts](/F:/.FinalProject/server/app.ts:1)、[server/routes](/F:/.FinalProject/server/routes)、[server/services](/F:/.FinalProject/server/services)、[server/tools/catalog.ts](/F:/.FinalProject/server/tools/catalog.ts:1)、[src/shared/apiClient.ts](/F:/.FinalProject/src/shared/apiClient.ts:1)，这说明项目已经完成了一轮架构拆分。

剩余主要问题变成：

- 控制平面状态编排仍集中在 [src/app/App.tsx](/F:/.FinalProject/src/app/App.tsx:44)。
- 本地存储仍集中在 [server/storage.ts](/F:/.FinalProject/server/storage.ts:131)。
- Agent 定义、prompt、默认 settings、文案仍集中在 [server/agentCards.ts](/F:/.FinalProject/server/agentCards.ts:1)。
- 生成链路仍集中在 [server/services/generationService.ts](/F:/.FinalProject/server/services/generationService.ts:18)。
- 前后端 DTO 有漂移风险，例如后端 `GenerateResponse.provider` 支持 `deerflow`，前端 [src/features/generation/types.ts](/F:/.FinalProject/src/features/generation/types.ts:19) 未包含。
- API 成功响应“直接返回 payload”是已记录的现状，见 [docs/API.md](/F:/.FinalProject/docs/API.md:1)，不应现在强行改成统一 envelope。
- 安全边界有文档约束，但 settings 写 `.env.local` 和未来 ToolUse bridge 还需要更强 policy guard。

## Key Changes

**1. 先修合同和文档事实，不做破坏性 API 统一**

- 保持 [docs/API.md](/F:/.FinalProject/docs/API.md:1) 当前约定：成功响应直接返回 payload，错误返回 `{ error }`。
- 不引入 `{ data }` envelope，避免重构过度。
- 新增 `shared/contracts/` 或 `server/contracts + src mirrored contracts` 的最小共享合同，优先覆盖 generation、provider、tools、agent runtime config。
- 修复 `GenerateResponse.provider` 前后端漂移：前端必须支持 `"deerflow"`。
- 所有结构变化同步更新 `docs/ARCHITECTURE.md`、`docs/AGENT.md`、`docs/API.md`、`docs/DATABASE.md`、`docs/SECURITY.md`、`docs/REFACTOR_LOG.md`，遵守 [docs/README.md](/F:/.FinalProject/docs/README.md:1) 的维护规则。

**2. 强化 FacetWrite 控制平面边界**

- 从 [src/app/App.tsx](/F:/.FinalProject/src/app/App.tsx:44) 抽出：
  - `src/app/hooks/useThreadSession.ts`
  - `src/app/hooks/useCanvasState.ts`
  - `src/app/hooks/useGenerationRun.ts`
  - `src/app/hooks/useProjectTrash.ts`
- `App.tsx` 只负责导航、布局和组合 hook。
- 线程创建统一走后端 `/api/threads`，不要在前端继续生成业务 thread id。
- Canvas write 仍保持 pending approval，不允许 Agent 或 DeerFlow 直接写 Canvas。

**3. 把 DeerFlow 当 runtime integration 管，不当普通参考代码处理**

- 保留 `server/deerflow/*` 作为一等集成层，因为文档已确认它是当前主 runtime path。
- `Deerflow/` 目录如果继续放在根目录，应标记为 sidecar source/vendor runtime，而不是当前 FacetWrite 应用代码。
- 建议改名或移动为 `integrations/deerflow-sidecar/`，但这一步排在后面，且必须更新文档和启动脚本。
- AI Dashboard 继续保持只读 runtime observability，不新增 DeerFlow 写配置 UI。

**4. 拆 Agent 定义和 Tool policy，但不重写 runtime**

- 拆 [server/agentCards.ts](/F:/.FinalProject/server/agentCards.ts:1)：
  - `server/agents/types.ts`
  - `server/agents/defaultSettings.ts`
  - `server/agents/cards/*.ts`
  - `server/agents/prompts/*.md` 或 `prompts.ts`
  - `server/agents/loader.ts`
- 修复 AgentCard 中文乱码，避免 prompt/文案继续混在难维护的大 TS 文件。
- 新增 `server/tools/toolPolicyGuard.ts`，在 [server/toolRuntime.ts](/F:/.FinalProject/server/toolRuntime.ts:31) 执行前统一校验 enabled、approval、external config、risk level。
- 不改变 `canvas_write` 现有语义：只能创建 pending request。

**5. 拆 storage 和 generation，但采用 facade 兼容迁移**

- [server/storage.ts](/F:/.FinalProject/server/storage.ts:131) 先拆 schema 和 repository，不改 SQLite 表名和 `.facetwrite/` 路径。
- 推荐目标：
  - `server/db/schema.ts`
  - `server/db/sqlite.ts`
  - `server/repositories/threadRepository.ts`
  - `server/repositories/canvasRepository.ts`
  - `server/repositories/agentSettingsRepository.ts`
  - `server/repositories/runRepository.ts`
  - `server/storage/index.ts` 作为兼容 facade
- [server/services/generationService.ts](/F:/.FinalProject/server/services/generationService.ts:18) 拆成：
  - `server/services/generation/generationService.ts`
  - `server/services/generation/promptRunBuilder.ts`
  - `server/services/generation/deerflowRunner.ts`
  - `server/services/generation/providerRunner.ts`
  - `server/services/generation/mockFallback.ts`
  - `server/services/generation/runRecorder.ts`

## Phased Plan

**Phase 1：合同、安全、乱码修复**

- 修复前后端 generation/provider 类型漂移。
- 增加 settings save 本地写入 policy：生产环境默认禁止写 `.env.local`。
- 修复 `server/agentCards.ts`、`server/services/generationService.ts`、局部 UI copy 中的中文乱码。
- 把 API validation 错误明确返回 400；保留现有成功响应格式。
- 跑 `npm.cmd run typecheck` 和 `npm.cmd test`。

**Phase 2：前端控制平面瘦身**

- 从 `App.tsx` 抽 thread/canvas/generation/project hooks。
- 前端停止自行生成业务 thread id。
- 拆 `ProjectSettingsPanel` 为 provider settings hook + DeerFlow status panel。
- 拆 `AgentSettingsView` 为 container + tab components。
- 不改 UI 视觉，不改路由，不改 API URL。

**Phase 3：Agent/Tool 配置层产品化**

- 拆 Agent cards、prompts、default settings。
- 新增 tool policy guard。
- Agent settings UI 继续从 runtime-config 渲染 tools/skills，不回到硬编码。
- 更新 `docs/AGENT.md` 和 `docs/SECURITY.md`。

**Phase 4：Storage 与 Generation 后端拆分**

- 先给现有 storage facade 补回归测试。
- 拆 schema/repositories，保留 `createStorage()` 对外行为。
- 拆 generation runners，保持 `generateAndRecord()` 对 routes 的入口不变。
- 保持 TypeScript fallback runtime，不移除 mock fallback。

**Phase 5：DeerFlow bridge 继续闭环**

- 不急着扩展更多复杂 ToolUse。
- 优先把 CanvasWrite、KnowledgeBase、WebSearch 的 bridge 状态从“配置传递”推进到“实际可验证消费”。
- AI Dashboard 增加最近 runtime event 可视化时，再更新 [docs/REFACTOR_LOG.md](/F:/.FinalProject/docs/REFACTOR_LOG.md:1)。

## Do Not Touch Yet

- 不要把所有 API 成功响应改成 `{ data }`，这和当前 [docs/API.md](/F:/.FinalProject/docs/API.md:1) 冲突，收益不够。
- 不要替换 SQLite 或引入 ORM；[docs/DATABASE.md](/F:/.FinalProject/docs/DATABASE.md:1) 明确未来 refactor 要保留表名和路径。
- 不要移除 TypeScript provider fallback；文档明确它是 DeerFlow disabled/unavailable 时的 fallback。
- 不要开放 DeerFlow 写配置 UI；当前 AI Dashboard 是只读 observability。
- 不要重做 UI 视觉系统；这轮只做结构、边界和可维护性。
- 不要把 `Deerflow/` 简单删除或当无关副本处理；它已经是当前 runtime sidecar 演进的一部分。
